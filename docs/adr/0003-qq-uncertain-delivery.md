# ADR-0003：QQ 消息发送结果不确定时，标记 UNKNOWN，不自动重发

- **状态**：已采用
- **日期**：2026-11-09（按当前代码重写）

## 背景

调用 QQ 接口发群消息时，可能出现这种情况：QQ 其实已经发出去了，但回给我们的响应在网络上丢了。这时网站和插件都无法从超时判断"到底发没发"。

如果当作没发成功再发一次，群里就会出现重复消息。对活动通知、报名提醒来说，重复刷屏的影响比偶尔漏发一条更糟。

## 决定

1. **领取、开始、回报三步走**（`packages/db/src/qq-official-notifications.ts`）
   - **领取（claim）**：插件领取待发送的消息时，网站用 `SKIP LOCKED` 选出消息，加上 30 秒的租约，并把版本号（fence）加 1。
   - **开始（begin）**：插件真正调用 QQ 之前，先告诉网站"开始发送"。网站核对消息 id、版本号和领取者都对得上，才把状态改为发送中（DISPATCHING）。
   - **回报（ack）**：发送完成后，插件把结果告诉网站。
   - 租约过期时，如果消息还停在"发送中"，就改为 **UNKNOWN**，不会重新进入待发送队列。

2. **插件本地账本**（`plugins/astrbot_plugin_artzoo/sender.py`）
   - 调用 QQ 之前，先在本地 SQLite 账本里记录"即将发送"，并且同步写入磁盘。
   - 每条消息只调用一次 QQ。结果不确定时，记为 UNKNOWN 并暂停这条消息。之后只重试"回报结果"这一步，不会重新发送消息。

3. **锁定 SDK 版本**（`plugins/astrbot_plugin_artzoo/sdk.py`）
   - 插件依赖 `qq-botpy` 的内部实现，所以要求版本必须正好是 1.2.1，并且会校验相关函数的源码哈希。
   - 关闭自动重定向，也关闭 SDK 自带的自动重试。

4. **默认不发送**
   - 网站这边的 `ARTZOO_QQ_MODE` 默认是关闭的，插件默认处于模拟模式。
   - 真实发送需要同时开启多项配置。

## 后果

- **好处**：断线、超时的时候不会刷屏重复发送。每一次实际调用 QQ，都能在账本里查到记录。
- **代价**：偶尔会有消息停在 UNKNOWN 状态，需要人工确认它到底发没发。
- **以后改动时要注意**：
  - 不要把 UNKNOWN 改成"自动重发"。
  - 插件升级、迁移时必须保留 SQLite 账本文件。不能删掉它，也不能用旧备份覆盖它，否则可能把已经发过的消息再发一遍。
  - 升级 `qq-botpy` 需要站长同意，并按插件 README 的步骤重新生成哈希。
  - 测试一律使用模拟，不能向真实的 QQ 群发消息。

## 相关代码

- `packages/db/src/qq-official-notifications.ts`：领取、开始、回报，租约与 UNKNOWN。
- `apps/web/server/qq-official/`：插件调用网站的接口，以及签名校验。
- `plugins/astrbot_plugin_artzoo/sender.py`：本地账本和发送控制。
- `plugins/astrbot_plugin_artzoo/sdk.py`：SDK 版本锁定。
