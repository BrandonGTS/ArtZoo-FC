# 心愿规则

心愿用来让成员说出"我想玩什么"，看看谁也有兴趣，凑够了人再转成正式活动。本文按代码版本 `fa643541` 核对过（主要代码在 `apps/web/server/wishes/`）。

---

## 1. 谁能做什么

| 操作 | 谁可以 |
|---|---|
| 浏览心愿、看感兴趣名单、看留言 | 所有登录用户。游客看不到任何心愿内容 |
| 发布心愿 | 正式成员，每小时最多 60 条 |
| 表达或取消兴趣、留言、回复 | 正式成员和朋友 |
| 修改心愿 | 原作者本人。即使作者后来变成了朋友，也还能修改 |
| 完成（删除）心愿 | 原作者本人 |
| 转成正式活动 | 原作者本人，并且转的时候必须仍然是正式成员 |
| 违规删除 | 只有超级管理员 |

心愿**不支持**由别人接手组织，管理员也不行。

## 2. 发布与修改

1. 标题必填，最多 100 字。
2. 分类必填，从以下六类中选一个：坐骑收集、高难挑战、生产采集、探索冒险、成就收集、其他心愿。
3. "想玩的内容"必填，最多 11001 字。
4. "方便时间"必填，最多 500 字。
5. 修改时带有版本号，防止两边同时改、互相覆盖。每次修改都会记下改之前和改之后的内容。修改时不能更换作者，也不能更换关联的活动。
6. 列表每页显示 15 条。

## 3. 兴趣

1. 可以表达兴趣、取消兴趣，也可以取消后再次表达。兴趣人数和名单只统计当前仍然有效的兴趣。
2. 兴趣只是意向，**不等于报名**，不占位置，也不会自动成团。
3. 感兴趣名单每页 10 人，按最近一次表达兴趣的时间排列。
4. 某人**第一次**对一条心愿表达兴趣时，作者会收到一条通知。这条通知每个人只会触发一次：取消后再表达，不会重复通知。作者对自己的心愿操作，不会收到通知。

## 4. 留言与回复

1. 留言最多 2000 字，文字和图片至少要有一样。每条留言最多 10 张图，每张最大 30 MB。
2. 回复只能针对同一条心愿下已有的留言。
3. **通知**：
   - 新留言会通知心愿作者。
   - 回复会同时通知心愿作者和被回复的人。
   - 同一条留言，同一个人只会收到一次通知；自己的留言不会通知自己。
4. 留言里可以 @ 成员，每条最多 @ 50 人。但被 @ 的人**不会收到通知**，@ 只是显示用的。
5. 留言**不能删除**，作者、心愿作者、管理员都删不了。留言也没有点赞功能。

## 5. 转成正式活动

1. 作者发起，沿用正式活动的发布流程和规则（见 [activities.md](activities.md)）。转的时候不会自动帮任何人报名。
2. **每条心愿只能关联一个活动**，转过一次以后就不能再转。
3. 转成功后，系统会通知当前所有感兴趣的人（作者本人除外）。之后新表达兴趣的人，也会补收一次"已有相关活动"的通知。
4. 关联的活动如果后来被取消了，心愿和活动之间的关联仍然保留，也不能再转一个新活动。这时通知标题会显示"相关活动已取消"，仍然可以点进去查看。
5. 心愿的显示状态只有两种：
   - "正在讨论"：还没有关联活动。
   - "已有相关活动"：已经关联了活动，活动被取消后也仍然显示这个状态。

## 6. 完成与违规删除

1. **作者完成**（界面上叫"完成心愿"）：
   - 需要明确确认，不需要填理由。
   - 已经关联了活动的心愿也可以完成。完成时会解除和活动的关联，**活动本身保留，不受影响**。
2. **超级管理员违规删除**：
   - 必须确认，填写理由（1–1000 字），并带上当前版本号。
   - 不会解除关联，也不会取消关联的活动。
   - 删除记录和理由会被保存下来。
3. 无论是完成还是违规删除：
   - 心愿、留言、图片都会从列表和详情里消失，直接访问会显示"不存在"。
   - **没有恢复入口。**
   - 不会单独通知作者。之前和这条心愿有关的通知，会统一显示为"相关心愿已删除"。

## 已知的问题与待定事项

- 留言可以 @ 别人，但不会发出通知。需要决定：是补上 @ 通知，还是把 @ 功能去掉。
- 心愿的留言没有任何人能删除，包括违规的留言。
- 服务端允许作者对自己的心愿表达兴趣，只是界面上没有提供这个按钮。
