# apps/web/server/auth：登录、会话、短信、限流（高风险）

这里的任何改动都属于高风险。动手前先读同目录的 `README.md`，并向站长说明改动范围和验证方式，得到同意后再开始。

## 不能改变的安全设计

修改以下任何一项，都必须先得到站长同意。

- **密码哈希**：使用 scrypt，比对时用 `timingSafeEqual`。手机号不存在时，也要用假哈希完整跑一遍比对，让响应时间保持一致。
- **会话 token**：随机生成，数据库里只存哈希。改密码或重置密码时，该账号的全部会话都要作废；被停用的账号要立即失效。
- **登录失败提示**：统一显示"手机号或密码不正确"，不能透露手机号是否已注册。
- **找回密码**：如果号码没有注册，不发短信，但返回给前端的结果要和成功时完全一样。
- **限流**：按来源 IP、账号、全局三层分别计数。来源只能通过 `resolveRequestSource` 获取。生产环境必须设置 `ARTZOO_TRUSTED_PROXY=caddy`。
- **Cookie**：生产环境使用 `__Host-` 前缀，并带上 `HttpOnly`、`SameSite=Lax`、`Secure`。

## 测试与外部服务

- 测试一律使用替身（stub）。**不得发送真实短信**，不得调用真实的短信服务商接口。
- 每次改动，都要覆盖三类情况：成功、失败，以及"失败时是否泄露了信息"（例如响应或耗时能不能看出号码是否存在）。

## 日志

不要记录以下内容：手机号、验证码、密码、token、邀请链接、请求体。
